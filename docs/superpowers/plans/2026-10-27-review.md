# Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admins can review candidate pairings (accept, reject, replace existing, undo), adjust the candidate threshold, add a mapping from two 7TV emote links, delete mappings and download a preset as JSON, at `/review`.

**Architecture:** One migration adds `rejections` and `settings`. A small worker module turns sightings into candidates with one SQL query; an admin-only Hono router (`/api/admin/*`) exposes the queue and the preset writes. A new `/review` page, built from the existing deck components and `Workbench.module.css`, calls that router; every write re-fetches the queue, and a toast offers Undo for the last decision.

**Tech Stack:** Cloudflare Worker + Hono + D1, zod; React 19 + react-router 8 + CSS modules; Vitest (jsdom for `src/`, `@cloudflare/vitest-plugin` for `worker/`).

**Spec:** `docs/superpowers/specs/2026-10-27-seasonal-emote-replacer-rebuild.md` ("Roles", "Candidates and review").

## Global Constraints

- Admin = a Twitch login in `ADMIN_LOGINS` (`wrangler.jsonc`, tests: `niena`); checked with the existing `isAdmin(env, login)`.
- Candidate: a (season, original, replacement) pairing with sightings from **at least 2 distinct channels** by default, not already that season's mapping, not rejected. A channel counts once per pairing.
- The threshold is adjustable in the admin view (stored in D1, integer 1–50).
- A pending candidate below the threshold is simply not listed; accepted mappings are never removed automatically.
- Review card: the two emote images side by side, Accept and Reject, one line `<alias> → <alias> · seen in N channels`. If the original is mapped to something else, the card shows the current mapping and Accept reads **Replace existing**.
- Rejections are permanent (no UI to list or lift them beyond the Undo toast). A short Undo toast follows each decision.
- Deleting a mapping does not reject it. D1 is the source of truth; `mappings.source` gains `'review'` and `'manual'`.
- Downloaded preset JSON has the `PresetFile` shape of `data/presets/<season>.json`: `{ season, mappings: [{ originalId, replacementId }] }`, sorted by `originalId`.
- English, plain and friendly; copy uses curly apostrophes (`’`) like the rest of the site. Orange (`ActionKey`) stays reserved for one committing key per screen; everything else is `GunmetalKey`.
- Admin responses are `Cache-Control: no-store` (the public preset endpoint keeps its 5-minute cache).

**Decision to confirm:** sightings store only the normal set’s alias (both sides share it by definition of a match), so the card line renders that alias on both sides of the arrow, e.g. `peepoHappy → peepoHappy · seen in 3 channels`.

## Review Focus

1. **Pasted emote links come in many shapes** (`https://7tv.app/emotes/ID`, with `?query`, `old.7tv.app`, a CDN image URL, a bare ID): all should resolve to the ID; anything else is refused with a message. Test in Task 4.
2. **Undoing a "Replace existing" accept** must put back the previous replacement with its original `source` (e.g. `seed`), not delete the mapping. Test in Task 2 and Task 3.
3. **A deleted mapping whose sightings still meet the threshold** comes back into the queue (deleting isn't rejecting). Test in Task 1.
4. **A signed-in non-admin or a signed-out visitor calling `/api/admin/*` directly** gets 403 / 401, never data. Test in Task 2.
5. **Adding a mapping with the same emote on both sides** is refused ("Pick two different emotes."), on the server as well as in the form. Test in Task 2 and Task 4.

- Produces (types in `shared/types.ts`):
  ```ts
  export type MappingSource = 'seed' | 'review' | 'manual';
  export interface AdminMapping extends MappingRow { source: MappingSource; createdAt: string }
  export interface ReviewResponse { season: SeasonId; threshold: number; candidates: Candidate[] }
  export interface AdminMappingsResponse { season: SeasonId; mappings: AdminMapping[] }
  export interface MappingWrite { season: SeasonId; originalId: string; replacementId: string; source: MappingSource }
  export interface MappingWritten { previous: AdminMapping | null }
  export interface MappingDeleted { deleted: AdminMapping | null }
  export interface RejectionRequest { season: SeasonId; originalId: string; replacementId: string }
  ```
- Routes (all `no-store`, all behind `requireAdmin`):
  - `GET  /api/admin/review/:season` → `ReviewResponse`
  - `PUT  /api/admin/threshold` `{ threshold: number }` → `{ threshold: number }`
  - `GET  /api/admin/mappings/:season` → `AdminMappingsResponse` (sorted by `originalId`)
  - `PUT  /api/admin/mappings` `MappingWrite` → `MappingWritten` (upsert on `(season, original_id)`; `previous` is the row it replaced)
  - `DELETE /api/admin/mappings/:season/:originalId` → `MappingDeleted`
  - `POST /api/admin/rejections` `RejectionRequest` → 201 `{}` (idempotent: `INSERT OR IGNORE`; `rejected_by` = session `twitchId`)
  - `DELETE /api/admin/rejections/:season/:originalId/:replacementId` → 204
- `requireAdmin: MiddlewareHandler<AppEnv>`: no session → 401 `{ error: 'Sign in with Twitch to review.' }`; signed in, not admin → 403 `{ error: 'Review is for admins.' }`; sets `c.var.user`.

- Produces `UndoToast({ message: string; onUndo(): void; onDone(): void; timeoutMs?: number })`: `role="status"`, a `GunmetalKey size="small"` labelled **Undo**, calls `onDone` after `timeoutMs` (default 8000).
- Produces `ReviewCard({ candidate: Candidate; onAccept(): void; onReject(): void; busy: boolean })`.

Page states (reuse the sign-in block pattern from `Compare.tsx`, return path `/review`):
- signed out: “Sign in with Twitch” (`signInUrl('/review')`), or the existing “not set up” plate when `signInAvailable` is false;
- signed in, not admin: plate **“Review is for admins.”** “You’re signed in as <displayName>.”;
- admin: season `Knob` (as in Compare), threshold field (`DeckField` label **“Channels needed”**, saved with a `GunmetalKey` **Save**), then the queue: heading “Waiting for review”, an `AmberScreen` readout `<Season> · N waiting`, one `ReviewCard` per candidate, or “Nothing is waiting for review in <Season>.” when empty.

Card: two `Keycap`s with an arrow (as in `SwapList`), the line `<alias> → <alias> · seen in N channels` (`1 channel` singular), when `current` is set a second line “Now mapped to” with that emote’s `Keycap`; buttons **Accept** / **Replace existing** and **Reject** (both `GunmetalKey`).

Decisions: Accept → `writeMapping({ …, source: 'review' })`, toast “Accepted <alias>.”; Undo → `previous ? writeMapping({ season, ...previous }) : deleteMapping(season, originalId)`. Reject → `rejectPairing`, toast “Rejected <alias>.”; Undo → `unrejectPairing`. After every write or undo, re-fetch the queue. A new decision replaces the toast. Failures show the server’s message in a `role="alert"` plate.
